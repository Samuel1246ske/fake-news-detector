# TruthGuard AI — Fake News Screening Prototype

A responsive frontend and a small FastAPI + scikit-learn backend for an educational news-text screening project.

> **Important limitation:** A text classifier cannot establish whether a story is true. It learns patterns in a labelled dataset and can reproduce dataset bias, miss context, or be fooled by satire and breaking news. The displayed confidence is model confidence, not the probability that a claim is true. Do not use this tool as the sole basis for deciding whether to share or reject a story.

## Repository layout

- `index.html`, `style.css`, `script.js` — GitHub Pages frontend.
- `backend/app.py` — JSON prediction API.
- `backend/train.py` — baseline TF-IDF + Logistic Regression training script.
- `backend/requirements.txt` — Python dependencies.
- `data/news.csv` — **you supply this**; it is intentionally not included.
- `model/fake_news_pipeline.joblib` — generated by training; not committed.

## 1. Publish the frontend on GitHub Pages

1. Create a public GitHub repository named `fake-news-detector`.
2. Upload the contents of this folder to the repository root (not the containing folder).
3. Open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**, branch `main`, folder `/ (root)`, then Save.
5. Wait for the Pages deployment to complete. The site address will look like `https://YOUR-USERNAME.github.io/fake-news-detector/`.

## 2. Train the model locally

Use a dataset you are permitted to use. Prepare `data/news.csv` with two columns:

```csv
text,label
"A complete news article or claim...",1
"Another labelled news article...",0
```

Convention: `1 = REAL`, `0 = FAKE`. Ensure labels are accurate, sources are documented, both classes are represented, duplicates and leakage are checked, and the test set is representative. Do not treat a random split as proof of real-world performance. Evaluate precision, recall, F1, confusion matrix, and performance across topics, languages, and publishers. For a credible research project, consider time-based and source-separated evaluation.

```bash
cd backend
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cd ..
python backend/train.py
```

This creates `model/fake_news_pipeline.joblib`.

## 3. Run the backend locally

```bash
pip install -r backend/requirements.txt
uvicorn backend.app:app --reload
```

API health check: `http://127.0.0.1:8000/`
API documentation: `http://127.0.0.1:8000/docs`

For production, deploy the backend to a Python-capable host. Set `ALLOWED_ORIGINS` to your exact GitHub Pages origin, e.g. `https://YOUR-USERNAME.github.io` (no trailing path). Keep the trained model file available to the backend at `model/fake_news_pipeline.joblib`. Do not put secrets in frontend JavaScript or GitHub.

## 4. Connect frontend to backend

In `script.js`, replace:

```js
const API_URL = "https://YOUR-BACKEND-URL.example.com";
```

with the deployed backend origin, e.g. `https://your-api-host.example.com`. Commit the change. The browser calls `POST /predict` with `{ "text": "..." }`.

## Current status

The frontend is ready for GitHub Pages. The API code is ready, but predictions remain disabled until a labelled dataset is supplied, the model is trained, and the backend is deployed. The UI deliberately avoids claiming that a text pattern proves a story is fake or real.
